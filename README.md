# 重庆大学数学建模秋季赛 C 题建模与复现

项目从赛题提供的摩拜订单 CSV 生成分区客流预测、调度计划、用户激励评估和围栏试点方案。

| 路径 | 用途 |
|---|---|
| [run.py](run.py) | 运行完整流程、导出表格和图表 |
| [bike_share/demand.py](bike_share/demand.py) | 订单读取、分区、OD 和客流预测 |
| [bike_share/operations.py](bike_share/operations.py) | 库存回放、调度和奖励，运营参数在 Settings 中 |
| [bike_share/fences.py](bike_share/fences.py) | 电子围栏设点、定容和多平台情景 |
| [environment.yml](environment.yml) | Conda 环境配置 |
| [data/](data/README.md) | 原始订单附件的本地放置说明 |

将原始 CSV 放到 `data/`。如果项目位于原有比赛工作区，也会自动查找相邻的赛题附件目录。可以用 `--data` 和 `--out` 指定输入和输出。

## 运行

在 PowerShell 中进入仓库目录。用本机 Conda 创建环境，或直接使用已经创建的 `.conda-env`：

    conda env create --prefix .\.conda-env --file .\environment.yml
    conda run --prefix .\.conda-env python -s -B -X utf8 .\run.py

如果 PowerShell 中的 conda 命令仍指向旧的 conda.bat，可用本机的 conda.exe 替代。输出保存在 `results/`，其中 CSV 使用 UTF-8 BOM。原始订单、运行输出与本地 Conda 环境均通过 `.gitignore` 排除。

## 数据与第一问

1. CSV 共 3,214,096 笔已完成订单。统计日期和小时覆盖，5 月 17 日整日无记录，20、23、24 日有完整小时无记录。这些日期未用于训练和回放。5 月 22 日作为低记录量的压力情景。保持 5 月 10–16 日训练、18 日验证、19、21、22 日测试。样本覆盖不能仅凭某小时有订单就认定完整。
2. 仅用训练样本选择 55 个高流量五位 Geohash 区，并把其中 7 个的高流量子区细分为六位网格。139 个可调度区域约占训练订单端点的 87.1%。其余端点合并到 EXTERNAL 以保留流量和车辆账。EXTERNAL 没有物理中心，不纳入调度或本文报告的模拟区域内未满足率。
3. 记 D_it 为区 i、时段 t 的出发量。按工作日和周末分别估计同一时段的训练均值。用同一训练集拟合泊松损失的直方图梯度提升树作为对照。树模型在小时尺度预测出发量，再按训练日小时内部的 15 分钟比例和 OD 构成分配。训练的历史均值特征按日剔除本日订单计算。
4. 用 \(\widehat F_{ijt}=\widehat D_{it}\widehat p_{ij,t}\) 表示预测的到达目的地区分布。这里的 t 为出发时段。出发量等于对应 OD 行和。用训练订单同一 OD 的平均直线距离换算还车滞后。树模型和历史均值用 5 月 18 日累计 OD 净流量 MAE 选型，WAPE 用于并列比较。该净流量指标按同一出发批次统计起点减终点差值，不含实测还车时间。

## 第二问：调度模型与回放

令 I_it 为区 i 当前可借库存，A_it 为本时段抵达的骑行，M_in 和 M_out 为按计划到达及被调运预留的车辆，S_it 为服务的借车请求。库存按
\(I_{i,t+1}=I_{it}+A_{it}+M^{in}_{it}-M^{out}_{it}-S_{it}\)
变化。分设骑行在途池和卡车调运池，只有车辆抵达才能进入目的区。每个 15 分钟时段都检查所有库存非负，以及停车、骑行在途和调运池之和等于初始车辆数。区域内部按出发时间回放，无法借到车的请求不会产生随后还车。

未来两小时的目标库存为预测累计净流出的最大正值，加下一小时预测出发量的 25% 作为缓冲。在 05–09、11–14、15–19 时段滚动派车。可供调运量为超过目标的当前库存，缺口为目标与当前库存加已计划调入的差值。先在近邻供需网络中求最大流，同等调运量下最小化载货运输距离。然后将运输任务分给附近的空闲车辆，计算空驶、重载、装卸和周转时间，并把车位留到对应到达时段。最小费用流只在运输量层面最优，完整的车辆路线采用启发式派车。

卡车数 18、每辆卡车容量 45 台单车、运输速度 25 km/h、道路距离修正 1.3，均为可更改的运营情景。采用同样的车队和出发条件比较不调度、就近调度和优化调度。里程是直线距离经过修正的近似值。

回放使用对应测试日的历史订单作为请求流。靠近午夜时仍可能在途的车辆单列。近期车辆最后一次可见落点只提供初始位置代理。用过去三天出现车辆的分区数乘以可用比例，并取整。主情景取 25%，对照 15%、40%、75% 和 100%；基准骑行速度 12 km/h，对照 9 和 16 km/h。实际库存、放弃借车量和骑行时长均未观测，因此这些情景不能推断真实未满足率。

## 第三问：用户奖励

对拟还车至预计盈余区的用户，如果附近区域存在缺口，推荐另一还车区。范围默认限定为 1 km 的区域中心距离代理。在模拟中，用户拟还车点取自原订单终点，对应实际部署时用户在应用中选择的目标。接受后替换原订单去向，不额外生成车辆。比较每次 0.8 元的固定奖励与根据距离和缺口在 0.4、0.8、1.2 元之间选择的动态奖励。每个时段同时限制要约数量、预计库存缺口和剩余预算。全天最多支出 600 元。

模拟接受概率为 \(\sigma(\alpha+2r-2.8d)\)，其中 r 为金额，d 为额外步行距离代理（千米），\(\alpha\) 用 -2.4、-1.4、-0.4 三档响应情景。附件没有发券实验，系数为假设。对照接受次数、平均额外步行、每次改停奖励、模拟未满足量和人工调运量。车辆原有骑行滞后在改停情景下保留，合理性取决于绕行相对较短；当前激励只按区域库存触发，尚未接入各围栏的实时空位。

## 第四问：围栏选址与容量

对三个训练期最繁忙的六位试点区，用七位终点生成候选停车单元。估计各单元小时借还流量后，用累计净流量的最小非负起始库存构建训练期停车占用代理。对测试日以训练期估计的初始量回放观测净流量并将负值截断为零，得到留出日占用代理。由于附件没有静态停车和完整还车时刻，它用于相对比较布局，不能作为现场实测库存。

对每区求解带容量的设施选址。二元变量 \(y_j\) 决定是否开设站点，\(x_{ij}\) 决定需求单元 i 是否分配给 j，整数 \(K_j\) 决定车位数。每个需求单元分到一个站点或记为未覆盖。候选步行距离最多 350 m（以中心直线距离计），容量受试点总车位预算及单站上限约束。对于每小时预测占用 \(Q_{it}\)，使 \(\sum_i x_{ij}Q_{it}\le K_j+u_{jt}\)，允许少量溢出 \(u_{jt}\) 并在目标中计罚。目标也惩罚未覆盖、步行和站点数量。参数采用相对权重，候选中心是规划点位，具体地块面积、通行距离和道路条件待核验。

以相同的站点数和总车位数比较热门点均分容量与优化布局。额外用 25%、50% 的竞争平台相对负荷比较共用围栏与固定 75/25 配额。报告覆盖、步行距离和占用溢出车时。围栏和多平台模型是独立的试点评估，尚未与全域逐单调度联立。
